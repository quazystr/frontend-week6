## Проверка поведения после рефакторинга (Task 6.1)

Поведение приложения осталось неизменным. Все сценарии из старой таблицы проверок проходят успешно:

1. Добавление задачи: валидация работает, задача появляется в списке, сохраняется в `localStorage` с ключом `week6:todo-tasks`.
2. Отметка выполнения: чекбокс переключается, счетчик обновляется, стиль задачи меняется.
3. Удаление задачи: задача исчезает из DOM и из хранилища.
4. Фильтрация: переключение между "Все", "Активные", "Выполненные" работает корректно.
5. Очистка выполненных: кнопка активна только при наличии выполненных задач, после нажатия они удаляются.
6. Стартовые задачи: при первом запуске (пустой `localStorage`) загружаются из `data/tasks.json`.
7. Импорт: кнопка загружает задачи из внешнего API, трансформирует их и добавляет в список.

### Архитектурные гарантии:

- **Нет глобальных переменных:** всё инкапсулировано в модулях.
- **`state.js`:** хранит данные в закрытых переменных, другие модули меняют состояние только через экспортируемые функции (`addTask`, `toggleTask` и т.д.).
- **`render.js`:** чистые функции, получают данные аргументами, не импортируют `api.js` или `storage.js`.
- **`api.js`:** не обращается к `document`.
- **Ключи хранилища:** используют префикс `week6:`.

## Проверка Task 6.2: Стартовые задачи с сервера

1. Первая загрузка (ключ в localStorage отсутствует):

- Что происходит: Приложение показывает `status--loading` ("Загрузка стартовых задач..."). Форма добавления при этом активна и работает.
- Результат: Загружается `data/tasks.json`, данные фильтруются через `isValidTask`, сохраняются в `localStorage` и отображаются. Статус меняется на `idle`, блок status скрывается.

2. Повторная загрузка (ключ есть, даже если массив пустой `[]`):

- Что происходит: Приложение НЕ делает запрос к `data/tasks.json`.
- Результат: Загружаются данные из `localStorage` (пустой массив). Пользователь видит пустой список, стартовые задачи не возвращаются насильно.

3. Ошибка загрузки (имитация через DevTools: Block request URL или Offline):

- Что происходит: Запрос падает.
- Результат: Показывается `status--error` с текстом "Не удалось загрузить стартовые задачи" и кнопкой "Повторить". Приложение продолжает работать с пустым списком задач. Форма добавления активна.
- Кнопка "Повторить": при нажатии очищает `localStorage` и запускает `fetchInitialTasks()` заново.

### Архитектурные гарантии:

- `storage.js` использует `localStorage.getItem() !== null` для точной проверки наличия ключа.
- `api.js` не знает о DOM и `localStorage`.
- `render.js` получает данные аргументами и не импортирует `api` или `storage`.
- Все ключи имеют префикс `week6:`.

## Проверка Task 6.3: Импорт из внешнего API

1. Успешный импорт новых задач:

- Действие: Нажата кнопка «Импортировать задачи».
- Результат: Кнопка стала недоступной, текст сменился на «Импорт...». Через мгновение появился зеленый `alert--success` с текстом «Импортировано: 5» (или другое число, если часть задач уже была в списке). Задачи добавились в список и сохранились в `localStorage`.

2. Повторный импорт (дедупликация):

- Действие: Сразу после успешного импорта нажата кнопка «Импортировать задачи» снова.
- Результат: Запрос ушел, но так как ID задач (`remote-1`, `remote-2` и т.д.) уже есть в списке, они не добавились второй раз. Появился зеленый алерт «Новых задач нет».

3. Защита от двойного клика:

- Действие: Включен Slow 3G в Network. Кнопка «Импортировать задачи» быстро нажата 5 раз подряд.
- Результат: Во вкладке Network виден ровно ОДИН запрос к `jsonplaceholder.typicode.com`. Остальные клики проигнорированы благодаря проверке `if (getStatus() === 'loading') return;` в начале обработчика.

4. Ошибка импорта (Offline или Block request URL):

- Действие: Включен Offline, нажата кнопка импорта.
- Результат: Кнопка заблокировалась на время запроса, затем разблокировалась. Появился красный блок `status--error` с текстом «Не удалось импортировать задачи». Существующие задачи не потеряны.

### Архитектурные гарантии:

- `fromRemoteTodo` возвращает `null` для невалидных данных, которые затем отсеиваются через `.filter(task => task !== null)`.
- Дедупликация работает на уровне сравнения `id` перед вызовом `addTask`.
- `api.js` не знает о DOM, `render.js` не знает о `fetch`.
- Кнопка меняет состояние (disabled + текст) исключительно на основе `state.status`, а не через прямое манипулирование классами в обработчике.

## Проверка Task 6.4: Ошибки сети

1. Централизация запросов:

- Все сетевые вызовы (`data/tasks.json` и внешний API) идут через единую функцию `request` с таймаутом 5 секунд (`AbortSignal.timeout(5000)`).

2. Обработка конкретных ошибок:

- Нет сети (Offline): показывается `alert--danger` с текстом «Нет соединения с сервером».
- Таймаут (Slow 3G): показывается «Сервер не ответил вовремя».
- Ошибка сервера (Block request URL / 404): показывается «Ошибка сервера: [код]».
- Испорченные данные: показывается «Сервер прислал испорченные данные».

3. Стабильность интерфейса:

- После любой ошибки кнопка «Импортировать задачи» или «Повторить» снова становится доступной (текст возвращается к исходному, `disabled` снят).
- Список задач не изменяется, так как мутация состояния (`addTask`, `setInitialTasks`) происходит только в блоке `try` до возникновения ошибки.
- В консоли нет «Uncaught» ошибок, все исключения перехвачены.

4. Две ошибки подряд:

- Если вызвать ошибку, а затем сразу еще одну (например, быстро нажать «Импортировать» при Offline, затем «Повторить»), таймер скрытия предыдущего алерта сбрасывается (`clearTimeout`). Новое сообщение останется на экране полные 5 секунд, а не исчезнет раньше времени.
