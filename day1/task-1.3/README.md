# Day 1, Task 1.3: Модуль валидации

## Результаты проверки `isEmail`

Функция корректно обрабатывает все граничные случаи без использования регулярных выражений:

- `""` и `"   "` → `false` (пустая строка или пробелы)
- `"a@b"` → `false` (нет точки после @)
- `"a@b."` → `false` (точка является последним символом)
- `"a@b.c"` → `true` (валидный минимальный формат)
- `" name@example.com "` → `true` (пробелы успешно удаляются через `trim()`)
- `"имя@почта.рф"` → `true` (кириллица поддерживается, так как используются методы строк, а не строгий ASCII-regex)
- `"a@@b.ru"` → `false` (более одного символа @, `split` вернет массив из 3 элементов)

## Результаты проверки `getGrade` и анализ значения `74.5`

При вызове `getGrade(74.5)` функция возвращает: **`'удовлетворительно'`**.

**Почему так решено:**

1. Значение `74.5` является числом, оно не равно `null`, не является булевым значением или пустой строкой, поэтому проходит начальные фильтры.
2. `Number(74.5)` возвращает `74.5`. Это не `NaN`, и оно находится в диапазоне `0 <= 74.5 <= 100`.
3. Условия проверяются последовательно сверху вниз:
   - `74.5 >= 90` → `false`
   - `74.5 >= 75` → `false`
   - `74.5 >= 60` → **`true`**
4. Как только условие `num >= 60` выполняется, функция немедленно возвращает `'удовлетворительно'` и прекращает дальнейшие проверки.

Хотя в словесном описании диапазона указано «60-74», в программной реализации условие `>= 60` математически корректно захватывает и дробные числа между 60 и 75 (например, 74.5), что является ожидаемым и правильным поведением для данной логики.

Все остальные тестовые значения (`0`, `59`, `60`, `74`, `75`, `89`, `90`, `100`, `-1`, `101`, `"80"`, `""`, `"   "`, `"abc"`, `null`, `true`) возвращают ожидаемые результаты согласно заданным правилам.
