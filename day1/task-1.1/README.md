# Day 1, Task 1.1: Модули и форматирование

## Проверка через `file://` (двойной клик по index.html)

При попытке открыть страницу двойным кликом (адрес в браузере начинается с `file:///`), в консоли появляется следующая ошибка:

> **Access to script at 'file:///.../day1/task-1-1/js/main.js' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: http, data, isolated-app, chrome-extension, chrome, https, chrome-untrusted.**

### Почему так происходит?

Браузеры применяют строгую политику безопасности **CORS** (Cross-Origin Resource Sharing). Когда страница открывается по протоколу `file://`, её "источник" (origin) считается `null`. Из соображений безопасности браузеры запрещают скриптам с `null`-источником загружать другие локальные файлы как модули (`type="module"`). Это предотвращает чтение злонамеренными скриптами файлов с жесткого диска пользователя.

## Проверка через Live Server

При запуске через расширение Live Server (или любой другой локальный сервер, например, `npx serve`), адрес страницы меняется на `http://127.0.0.1:5500/...`.

В этом случае:

1. Источник (origin) становится `http://127.0.0.1:5500`, что является допустимым протоколом.
2. Ошибка CORS исчезает.
3. Модуль `format.js` успешно загружается, импортируется в `main.js`, и в консоли корректно выводятся все 12 проверок (6 для цены и 6 для даты).
4. Проверка `formatDate(null)` успешно возвращает `"Дата не указана"`, а не `"01.01.1970"`, благодаря явной проверке на `null` до вызова `new Date()`.
