# Day 1, Task 1.5: Хранилище модулем

## Результаты проверок

### 1. Ключа нет

**Результат:** `'fallback_value'`  
**Почему:** `localStorage.getItem` возвращает `null`, если ключ не найден. Функция явно проверяет это условие и сразу возвращает `fallback`.

### 2. Лежит `'[1,2]'`

**Результат:** `[1, 2]` (массив)  
**Почему:** Строка является валидным JSON. `JSON.parse` успешно преобразует её в массив JavaScript, и `try` блок возвращает этот массив.

### 3. Лежит оборванная строка `'{"a":'`

**Результат:** `'fallback_value'`  
**Почему:** Строка не является валидным JSON. При вызове `JSON.parse('{"a":')` выбрасывается `SyntaxError`. Блок `catch` перехватывает эту ошибку и возвращает `fallback`, предотвращая падение приложения.

### 4. Лежит строка `'undefined'`

**Результат:** `'fallback_value'`  
**Почему:** Важно отличать примитив `undefined` от строки `'undefined'`. `localStorage` хранит только строки. `JSON.parse('undefined')` выбрасывает `SyntaxError` (так как это не валидный JSON, в отличие от `'null'` или `'true'`). Ошибка перехватывается, возвращается `fallback`.

### 5. `saveJson` с циклической ссылкой

**Результат:** `false`  
**Почему:** При попытке выполнить `JSON.stringify` на объекте, который ссылается сам на себя (`circularObj.self = circularObj`), движок JavaScript выбрасывает ошибку:  
`TypeError: Converting circular structure to JSON`.  
Наша функция оборачивает этот вызов в `try...catch`. Ошибка перехватывается, в `localStorage` ничего не записывается, а функция корректно возвращает `false`, позволяя программе продолжить работу без краша.

## Вывод

Использование `try...catch` при работе с `JSON.parse` и `JSON.stringify` является обязательной практикой при сохранении и чтении данных из `localStorage`, так как мы не можем гарантировать целостность данных, хранящихся на стороне клиента.
