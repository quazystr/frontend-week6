# Day 1, Task 1.2: Область видимости и выполнение модулей

## Часть 1: Проверка области видимости в консоли

При вводе команд в консоль браузера получены следующие результаты:

1. `pageName` ➔ Выводит: `'обычный'`
2. `window.pageName` ➔ Выводит: `undefined`
3. `moduleName` ➔ Выводит: `Uncaught ReferenceError: moduleName is not defined`
4. `window.moduleName` ➔ Выводит: `undefined`

**Почему так происходит:**

- Обычные скрипты выполняются в глобальной области видимости. Переменная `pageName` объявлена через `const`, поэтому она доступна в консоли по имени. Однако, согласно спецификации ES6, переменные, объявленные через `const` или `let` на верхнем уровне, **не становятся свойствами глобального объекта `window`** (в отличие от устаревшего `var`). Поэтому `window.pageName` возвращает `undefined`.
- Модули (`type="module"`) имеют собственную, изолированную область видимости. Переменная `moduleName` не видна ни в глобальной области, ни в объекте `window`. Чтобы передать данные из модуля наружу, их необходимо явно экспортировать (`export`).

## Часть 2: Проверка однократного выполнения модуля

В файл `js/format.js` добавлена строка `console.log('format.js выполнен')`. Этот файл импортируется в двух разных модулях: `main.js` и `second.js`.

**Результат в консоли:**
Строка `'format.js выполнен'` появилась в консоли **ровно 1 раз**.

**Почему так происходит:**
Спецификация ES-модулей гарантирует, что каждый модуль выполняется (инициализируется) **только один раз** за время жизни страницы.
Когда браузер встречает первый `import './format.js'` (в `main.js`), он загружает файл, выполняет его код и сохраняет результат в внутреннем кэше модулей. Когда браузер встречает второй `import './format.js'` (в `second.js`), он не выполняет код файла заново, а просто берет уже выполненный и закэшированный экземпляр модуля. Это предотвращает дублирование кода, экономит ресурсы и гарантирует, что состояние модуля остается единым для всей программы.
