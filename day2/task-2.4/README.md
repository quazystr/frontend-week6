# Day 2, Task 2.4: Проверка и фильтрация ответа

Реализованы функции `isValidTodo(item)` для строгой проверки одной задачи и `pickValid(items)` для безопасной фильтрации массива.

## Результаты тестов

1. Проверка реального ответа API (JSONPlaceholder)

- Результат: Из 20 полученных задач валидными оказались все 20. Функция корректно подтвердила, что тестовый API отдает данные в ожидаемом формате.

2. Проверка ручного массива с мусором

- Исходный массив содержал 6 элементов. После фильтрации `pickValid` остался ровно 1 элемент.
- Почему остальные были отброшены:
  - `null` и `'задача'`: не являются объектами.
  - `{ id: '1', ... }`: поле `id` является строкой, а ожидается целое число.
  - `{ id: 2, title: '   ', ... }`: поле `title` после `.trim()` становится пустой строкой.
  - `{ id: 3, title: 'ok', completed: 'false', ... }`: поле `completed` является строкой `'false'`, а ожидается строгий boolean (`true` или `false`).
- Оставшаяся задача (`id: 4`) прошла все проверки и была возвращена.

3. Проверка `pickValid({})` (передача объекта вместо массива)

- Результат: Вернулся пустой массив `[]`.
- Почему: Функция `pickValid` начинается с проверки `!Array.isArray(items)`. Поскольку `{}` не является массивом, функция сразу возвращает `[]`, не пытаясь вызвать метод `.filter()`, что предотвращает падение приложения с ошибкой `TypeError: items.filter is not a function`.

## Вывод

Использование защитного программирования (проверка типов и структур до их использования) гарантирует, что даже при получении некорректных или неожиданных данных от сервера приложение продолжит работать стабильно.
