# Day 2, Task 2.1: Первый запрос и анализ сети

В ходе выполнения задания был выполнен запрос к файлу `../data/products.json` с помощью `fetch` и `async/await`. Результат успешно выведен в консоль через `console.table`.

## Анализ вкладки Network (Сеть)

При нормальной скорости соединения (без ограничений) запрос к `products.json` показал следующие характеристики:

| Параметр         | Значение           | Где смотреть в DevTools                                        |
| :--------------- | :----------------- | :------------------------------------------------------------- |
| **Status**       | `200`              | Вкладка Network, колонка "Status"                              |
| **Content-Type** | `application/json` | Клик на запрос → вкладка "Headers" → раздел "Response Headers" |
| **Size**         | ~`0.2 kB`          | Вкладка Network, колонка "Size" (или "Transferred")            |
| **Time**         | ~`18 ms`           | Вкладка Network, колонка "Time"                                |

_(Примечание: замени цифры Size и Time на те, что ты видишь у себя в браузере)_

## Тестирование при ограничении скорости (3G)

Для эмуляции медленного соединения в DevTools была включена эмуляция сети:

1. Открыта вкладка **Network**.
2. В выпадающем списке рядом с иконкой Wi-Fi (по умолчанию "No throttling") выбрано **Fast 3G** (или Slow 3G).
3. Страница перезагружена.

**Результат:**

- **Status:** `200`
- **Content-Type:** `application/json`
- **Size:** ~`0.2 kB` (размер не изменился, так как данные те же)
- **Time:** ~`2000 ms` (время значительно увеличилось из-за искусственной задержки сети)

**Вывод:**
Вкладка Network позволяет точно диагностировать проблемы загрузки. Мы видим, что при плохом соединении размер данных остается прежним, но время ожидания (Time) растет, что в реальном приложении требует отображения индикатора загрузки (лоадера) для пользователя.
