# Day 2, Task 2.3: Внешний API (JSONPlaceholder)

## Результаты запросов

1. Запрос к `https://jsonplaceholder.typicode.com/todos?userId=1`

- Что в консоли: Всего задач: 20. Первые три названия: массив из трех строк (например, "delectus aut autem", "quis ut nam facilis et officia qui", "fugiat veniam minus").

2. Запрос к `https://jsonplaceholder.typicode.com/todos?userId=1&_limit=5`

- Что в консоли: Всего задач с лимитом: 5. Параметр `_limit` успешно ограничил выборку на стороне сервера.

3. Запрос к `https://jsonplaceholder.typicode.com/todos/99999`

- Статус, который вернул сервер: 404
- Тело ответа: пустой объект `{}`
- Что попало бы в программу без проверки `response.ok`: Функция `response.json()` успешно распарсила бы пустой объект `{}` и вернула его. Программа подумала бы, что запрос прошел успешно, и при попытке обратиться к свойствам задачи (например, `task.title`) получила бы `undefined`, что привело бы к скрытым логическим ошибкам или падению интерфейса позже.

## Сравнение структур задач

Поля задачи из JSONPlaceholder:

- `userId` (число): ID пользователя, которому принадлежит задача.
- `id` (число): Уникальный идентификатор задачи.
- `title` (строка): Название задачи.
- `completed` (логическое): Статус выполнения (true/false).

Поля задачи из нашего «Списка задач» (Todo App):

- `id` (строка, UUID): Уникальный идентификатор задачи.
- `title` (строка): Название задачи.
- `done` (логическое): Статус выполнения (true/false).
- `priority` (строка): Уровень приоритета ('low', 'normal', 'high').
- `createdAt` (строка, ISO-дата): Время создания задачи.

Главные отличия:

1. Имя поля статуса: `completed` во внешнем API против `done` в нашем приложении.
2. Тип ID: число во внешнем API против строки (UUID) в нашем приложении.
3. Внешнее API содержит ссылку на владельца (`userId`), но не содержит данных о приоритете и времени создания, которые есть в нашей модели данных.
