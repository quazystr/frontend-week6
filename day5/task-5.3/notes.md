# Day 5: Заметки по всем заданиям

## Task 5.1: Карточка пользователя

### Какие запросы уходят

- GET /users — для заполнения select списком пользователей.
- GET /users/:id — данные конкретного пользователя (имя, email, город, компания).
- GET /todos?userId=:id — список задач пользователя для подсчёта выполненных.
  Запросы к /users/:id и /todos?userId=:id выполняются одновременно через Promise.all.

### Состояния страницы

- idle — начальное состояние, до первого запроса.
- loading — идёт загрузка, select недоступен, показан блок status--loading с текстом «Загрузка данных...».
- success — данные успешно загружены, показана карточка пользователя с текстом «Выполнено: 11 из 20».
- error — произошла ошибка, показан блок status--error с текстом ошибки и кнопкой «Повторить».

### Какая функция меняет состояние и какая выводит его на страницу

- loadUserData(userId) — async-функция, которая меняет state.status, state.data и state.error. Внутри неё используется Promise.all для параллельных запросов и счётчик requestToken для защиты от состояния гонки.
- render() — единственная функция, которая читает state и обновляет DOM: управляет disabled у select, показывает/скрывает блоки status и user-card, заполняет поля карточки через textContent.

### Какие ошибки проверены и с каким результатом

- Offline: запрос падает, показывается status--error с текстом «Нет соединения с сервером» и кнопкой «Повторить».
- Быстрая смена пользователя на 3G: благодаря счётчику requestToken старый ответ отбрасывается, на странице остаются данные последнего выбранного пользователя.
- Ошибка в одном из двух запросов Promise.all: весь Promise.all падает, срабатывает catch, показывается ошибка и кнопка «Повторить».

## Task 5.2: Работа без сети

### Какие запросы уходят

- GET ../../data/products.json — локальный файл с товарами. Путь обрабатывается умной проверкой в api.js (начинается с точки, поэтому BASE_URL не добавляется).

### Состояния страницы

- idle — начальное состояние.
- loading — идёт загрузка, показан блок status--loading с текстом «Загрузка товаров...».
- success — данные успешно загружены с сервера, показаны карточки товаров, данные сохранены в localStorage под ключом 'week6:products-cache' с timestamp.
- cached — запрос упал, но есть кэш. Показаны карточки из кэша, сверху жёлтый alert--warning с текстом «Нет связи с сервером. Показаны данные от 14:05» (время форматируется через toLocaleTimeString('ru-RU')).
- error — запрос упал и кэша нет. Показан блок status--error с текстом ошибки и кнопкой «Повторить».

### Какая функция меняет состояние и какая выводит его на страницу

- loadProducts() — async-функция, которая меняет state.status, state.products, state.error и state.cacheTime. Внутри try/catch: при ошибке пытается прочитать кэш через loadFromCache().
- saveToCache(products) — безопасно сохраняет данные в localStorage с timestamp, оборачивает setItem в try/catch для защиты от QuotaExceededError.
- loadFromCache() — безопасно читает кэш: оборачивает getItem и JSON.parse в try/catch, валидирует структуру (должен быть объект с data-массивом и timestamp-числом). При любой ошибке возвращает null.
- render() — единственная функция, которая читает state и обновляет DOM: управляет блоками cache-alert, status, card-list.

### Какие ошибки проверены и с каким результатом

- Offline после успешной загрузки: запрос падает, срабатывает fallback на кэш, показаны карточки с жёлтым предупреждением о времени кэширования.
- Offline без кэша: запрос падает, кэша нет, показан status--error с текстом «Нет соединения с сервером» и кнопкой «Повторить».
- Испорченный вручную кэш (вкладка Application): JSON.parse выбрасывает SyntaxError, перехваченный в try/catch функции loadFromCache(). Функция возвращает null, приложение не падает, показывается обычная ошибка сети с кнопкой «Повторить».
- Возврат в Online: нажатие «Повторить» успешно перезагружает данные с сервера, кэш перезаписывается свежими данными, жёлтый алерт исчезает.

## Task 5.3: Итоговая сводка дня

### Проверка дня (выполнена)

1. Независимые запросы идут одновременно.

- В task-5-1 при выборе пользователя во вкладке Network видно два запроса: GET /users/:id и GET /todos?userId=:id.
- В колонке Waterfall их полоски начинаются примерно в одно и то же время и идут параллельно.
- Общее время загрузки равно времени самого долгого запроса, а не сумме обоих.

2. Без сети страница показывает кэш или понятную ошибку.

- В task-5-2 при Offline и наличии кэша показаны карточки с жёлтым предупреждением.
- При Offline без кэша показан понятный текст «Нет соединения с сервером» и кнопка «Повторить».
- Пользователь никогда не остаётся с пустым экраном и непонятной технической ошибкой.

3. В консоли нет «Uncaught».

- Все ошибки перехвачены в try/catch.
- AbortError корректно обрабатывается (не показывается пользователю).
- Ошибки парсинга кэша перехватываются в loadFromCache() и не ломают страницу.
- Ошибки квоты localStorage перехватываются в saveToCache().

### Ключевые принципы, применённые в дне

- Promise.all для параллельных независимых запросов.
- Защита от состояния гонки через счётчик requestToken.
- Кэш в localStorage как запасной вариант, а не источник правды.
- Безопасный парсинг JSON с валидацией структуры.
- Одна функция render() на все состояния страницы.
- Время для человека через toLocaleTimeString('ru-RU').
- Умная обработка путей в api.js (локальные файлы vs API).
