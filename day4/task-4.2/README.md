# Day 4, Task 4.2: Изменение и удаление задач

## Что реализовано

- Загрузка 5 задач через `GET /todos?userId=1&_limit=5`.
- Использование блоков `task-list` и `task` для отображения.
- Делегирование событий: один обработчик `change` на `.task-list` для чекбоксов и один `click` для кнопок удаления.
- Пока запрос выполняется, задаче присваивается модификатор `task--pending`, а её чекбокс и кнопка получают атрибут `disabled`.
- **Ключевое правило**: массив `state.tasks` изменяется (поле `completed` или удаление элемента через `splice`) **только** внутри блока `try` после успешного `await`.
- При ошибке запроса данные в массиве не меняются. Блок `finally` снимает флаг `isPending`, и функция `render()` возвращает чекбокс в прежнее положение, одновременно показывая сообщение об ошибке в блоке `alert--danger`.

## Проверка блокировкой запроса (DevTools)

1. Открыта вкладка Network.
2. На любом запросе к `jsonplaceholder.typicode.com` нажат правый клик → **Block request URL**.
3. На странице попытался изменить чекбокс или нажать «Удалить».

**Результат:**

- Задача мгновенно получила полупрозрачный вид (`task--pending`), элементы управления заблокировались.
- Через мгновение (когда fetch выбросил ошибку сети) задача вернулась в исходное состояние: чекбокс отщелкнулся обратно (или остался на месте, если это было удаление), модификатор `pending` исчез.
- Вверху страницы появился красный блок `alert--danger` с текстом: "Не удалось обновить задачу. Проверьте соединение." (или "Не удалось удалить...").
- В консоли нет необработанных ошибок (Uncaught), так как ошибка перехвачена в `catch`.

## Почему это надежная архитектура

Использование блока `finally` для сброса флага `isPending` гарантирует, что интерфейс никогда не "зависнет" в состоянии загрузки, даже если произойдет непредвиденная ошибка. А отложенное изменение массива данных до момента ответа сервера (Optimistic UI без отката, или Pessimistic UI с откатом) в данном случае реализовано как **Pessimistic UI**: мы ждем подтверждения сервера, прежде чем показать пользователю изменение как свершившийся факт. Это предотвращает рассинхронизацию интерфейса и реальных данных на сервере.
