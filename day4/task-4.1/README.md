# Day 4, Task 4.1: Отправка формы

## Что реализовано

- Форма на блоках `field` с валидацией: заголовок 3-100 символов, текст 10-1000 символов (после `trim`).
- Ошибки отображаются через модификатор `field--error` с текстом в `field__hint`.
- При ошибке валидации фокус автоматически перемещается на первое невалидное поле.
- Ошибка снимается динамически при вводе корректных данных (live-валидация).
- При отправке кнопка блокируется (`disabled`), текст меняется на «Отправка...».
- Успех: форма очищается, показывается `alert--success` с ID нового поста из ответа сервера.
- Ошибка (например, Offline): показывается `alert--danger` с понятным текстом, введенные данные сохраняются в полях.

## Анализ вкладки Network (при успешной отправке)

1. Payload (Отправляемые данные):

- В разделе Payload (или Request Payload) виден JSON-объект, который мы отправили:
  `{"title":"Мой заголовок","body":"Мой текст длиной более 10 символов","userId":1}`
- Это работает благодаря `JSON.stringify(body)` и заголовку `Content-Type: application/json` в функции `request`.

2. Response (Ответ сервера):

- В разделе Response виден JSON, который вернул сервер:
  `{"title":"Мой заголовок","body":"Мой текст длиной более 10 символов","userId":1,"id":101}`
- Сервер добавил поле `"id": 101` к нашим данным.

## Почему после перезагрузки поста 101 на сервере нет?

JSONPlaceholder — это учебный (mock) сервер. Он запрограммирован имитировать поведение настоящего REST API: он принимает POST-запросы, валидирует их и возвращает правдоподобный ответ со статусом 201 и новым ID (всегда 101 для постов).

Однако у него **нет настоящей базы данных**. Он не сохраняет полученные данные в память между запросами. При каждой перезагрузке страницы или новом GET-запросе он отдает один и тот же статический набор из 100 постов, который был заложен в его код при создании. Поэтому наш пост с ID 101 существует только в моменте ответа на конкретный POST-запрос и исчезает при следующем обращении к списку.

- Состояние `loading` корректно блокирует повторные нажатия.
