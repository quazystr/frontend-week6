# Day 4, Task 4.4: Поиск без лишних запросов

## Что реализовано

- Поле поиска в блоке `field`. При вводе пустой строки или строки из пробелов запрос не отправляется, появляется подсказка «Введите запрос».
- Задержка (debounce) 300 мс: запрос уходит только через 300 мс после того, как пользователь перестал печатать (используется `setTimeout` и `clearTimeout`).
- Отмена устаревших запросов: если пользователь продолжает печатать и уходит новый запрос, предыдущий принудительно обрывается через `AbortController.abort()`.
- Ошибка `AbortError` тихо игнорируется (функция `getErrorMessage` возвращает `null`), пользователь не видит сообщений об отмене.
- Если массив результатов пуст, выводится сообщение «Ничего не найдено по запросу «...»». Текст запроса вставляется через `textContent` для защиты от XSS.
- Текст запроса в URL безопасно кодируется через `encodeURIComponent`.

## Проверка на ограниченной сети (3G)

1. Включен режим Fast 3G или Slow 3G во вкладке Network.
2. В поле поиска быстро набрано слово «dolor».
3. Во вкладке Network видно, что запросы к `/posts?q=d`, `/posts?q=do` и т.д. имеют статус `(canceled)` и прерываются.
4. До сервера доходит только один финальный запрос: `/posts?q=dolor`.
5. На странице отображаются результаты именно для запроса «dolor», а не для промежуточных значений. Лишние запросы не завершаются успешно и не перезаписывают состояние.

## Проверка дня (выполнена)

- Используется `AbortController` для отмены устаревших запросов.
- Ошибка `AbortError` не выводится пользователю.
- Валидация пустого ввода работает до отправки запроса.
- Вставка пользовательского ввода в DOM выполняется строго через `textContent`.
- В консоли нет необработанных ошибок (Uncaught).
