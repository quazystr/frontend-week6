# Day 4, Task 4.5: Итоговая таблица сетевых проблем

## Ниже — финальная сводка всех сценариев, которые были проверены в течение Дня 4. Формат: что сделал → что увидел пользователь → что во вкладке Network.

1. Обычная отправка поста (task-4-1)

- Что сделал: ввел валидный заголовок и текст, нажал «Опубликовать».
- Что увидел пользователь: кнопка стала недоступной с текстом «Отправка...», затем появился зеленый alert--success с текстом «Пост создан, номер 101», форма очистилась.
- Что в Network: POST-запрос к /posts, Status 201. В Payload — JSON {"title":"...","body":"...","userId":1} с заголовком Content-Type: application/json. В Response — тот же JSON с добавленным полем "id":101.

2. Отправка поста в режиме Offline (task-4-1)

- Что сделал: ввел заголовок и текст, включил Offline, нажал «Опубликовать».
- Что увидел пользователь: кнопка на мгновение стала «Отправка...», затем разблокировалась. Введенный текст остался в полях. Появился красный alert--danger с текстом «Нет соединения с сервером».
- Что в Network: POST-запрос со статусом (failed), Size 0 B, Time ~0 мс.

3. Двойной клик по «Опубликовать» (task-4-1)

- Что сделал: быстро нажал кнопку «Опубликовать» два раза подряд.
- Что увидел пользователь: кнопка один раз стала «Отправка...» и заблокировалась. В Network — ровно один POST-запрос. Форма очистилась один раз.
- Что в Network: один запрос к /posts со статусом 201. Второй клик не отправил запрос благодаря проверке if (state.status === 'loading') return; в начале обработчика.

4. PATCH задачи при заблокированном адресе (task-4-2)

- Что сделал: во вкладке Network заблокировал jsonplaceholder.typicode.com через «Block request URL», затем нажал на чекбокс задачи.

- Что увидел пользователь: задача на мгновение стала полупрозрачной с модификатором task--pending, чекбокс и кнопка удаления заблокировались. Через мгновение задача вернулась в исходное состояние (чекбокс отщелкнулся обратно), появился красный alert--danger с текстом «Не удалось обновить задачу. Проверьте соединение.»

- Что в Network: PATCH-запрос со статусом blocked:devtools. Массив state.tasks не изменился, потому что изменение поля completed происходит только в блоке try после успешного await.

5. Удаление задачи в режиме Offline (task-4-2)

- Что сделал: включил Offline, нажал кнопку «Удалить» у задачи.
- Что увидел пользователь: задача стала полупрозрачной (task--pending), затем вернулась в список в исходном виде. Появился красный alert--danger с текстом «Не удалось удалить задачу. Проверьте соединение.»
- Что в Network: DELETE-запрос со статусом (failed). Задача не была удалена из массива, потому что state.tasks.splice() находится только в блоке try.

6. Загрузка фото на обычной сети (task-4-3)

- Что сделал: нажал «Загрузить фото» при обычном интернете.
- Что увидел пользователь: кнопка стала «Загрузка...» и заблокировалась, через доли секунды появился зеленый блок с текстом «Загружено фото: 5000».
- Что в Network: GET-запрос к /photos, Status 200, Size ~1 МБ, Time ~300–600 мс. Запрос уложился в таймаут 3 секунды.

7. Загрузка фото на 3G (task-4-3)

- Что сделал: включил Slow 3G, нажал «Загрузить фото».
- Что увидел пользователь: кнопка стала «Загрузка...», через ровно 3 секунды запрос оборвался, появился красный блок status--error с текстом «Сервер не ответил за 3 секунды» и кнопкой «Повторить».
- Что в Network: GET-запрос к /photos, Status (failed) или canceled, Time ровно 3000 мс (или чуть больше). Браузер принудительно оборвал запрос через AbortSignal.timeout(3000).

8. Быстрый ввод в поиске на 3G (task-4-4)

- Что сделал: включил Slow 3G, быстро набрал в поле поиска слово «dolor» (буква за буквой).
- Что увидел пользователь: после остановки ввода через 300 мс появился статус «Поиск...», затем результаты именно для запроса «dolor» (или сообщение «Ничего не найдено по запросу «dolor»»). Промежуточные результаты для «d», «do», «dol» не отображались.
- Что в Network: 5 запросов к /posts?q=..., из них 4 имеют статус (canceled) — они были отменены через AbortController.abort() при появлении следующей буквы. До сервера дошел только один финальный запрос /posts?q=dolor.

9. Поиск из одних пробелов (task-4-4)

- Что сделал: ввел в поле поиска строку из пробелов " ".
- Что увидел пользователь: запрос не ушел, в field\_\_hint появилась подсказка «Введите запрос». Список результатов скрыт, блок статуса скрыт.
- Что в Network: ни одного запроса не отправлено. Проверка query.trim() === '' сработала до установки таймера setTimeout, поэтому fetch даже не вызывался.
