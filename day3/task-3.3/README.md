# Day 3, Task 3.3: Пустой ответ и неверный ответ

## Что добавлено

- В select «Источник данных» добавлены варианты empty.json и object.json.
- Создан файл day3/data/object.json с содержимым { "items": [] }.
- После запроса проверяется форма ответа: если пришёл не массив, выбрасывается SyntaxError, и пользователь видит ошибку «Сервер прислал испорченные данные».
- Для пустого массива показывается блок empty с текстом «Товаров нет». Блок status при этом скрыт, модификаторы status--loading и status--error не выставляются.

## Почему пустой массив — это успех, а объект вместо массива — ошибка

Пустой массив [] — это корректный ответ правильной формы. Сервер понял запрос, обработал его и сообщил: «по этому запросу товаров нет». Это штатная ситуация предметной области: фильтр мог не совпасть ни с одним товаром, каталог мог опустеть. Ошибки не произошло, поэтому статус success, а интерфейс показывает нейтральное пустое состояние «Товаров нет» без кнопки «Повторить»: повторять запрос бессмысленно, ответ будет тем же.

Объект { "items": [] } — это ответ неправильной формы. Приложение договорилось с сервером, что каталог приходит массивом, и весь код рассчитывает на массив: перебор for...of, свойство length, методы filter и map. Если молча принять объект за данные, приложение не упадёт сразу, но покажет пустой каталог, как будто товаров нет. Это ложный вывод: товары, возможно, есть, просто лежат в другом поле. Скрытая порча данных опаснее явной ошибки, поэтому несовпадение формы ответа считается ошибкой контракта и попадает в статус error с текстом «Сервер прислал испорченные данные» и кнопкой «Повторить».

Технически это одна проверка Array.isArray(data) сразу после запроса. Если проверка не прошла, выбрасывается SyntaxError, который функция getErrorMessage переводит в понятный человеку текст — тот же, что и для невалидного JSON. Пользователю не важно, сломался парсер или пришла не та структура: в обоих случаях сервер прислал данные, которые приложение не может использовать.

## Проверка дня (выполнена)

- response.json() вызывается только после проверки response.ok.
- В try находится только запрос и проверка формы ответа, render вызывается после try/catch.
- Каждая ошибка поймана и превращена в текст для человека через getErrorMessage.
- В консоли нет «Uncaught (in promise)».
- Состояние читается только из state.status, а не из DOM; все переключения идут через одну функцию render.
