# Day 3, Task 3.2: Ошибка и «Повторить»

## Что реализовано

- Служебный select «Источник данных» с тремя вариантами: products.json, missing.json, broken.json.
- При выборе нового источника автоматически запускается загрузка данных.
- При ошибке блок status получает модификатор status--error и текст из функции getErrorMessage.
- Кнопка «Повторить» (status\_\_retry) появляется только при ошибке и повторяет тот же запрос.
- Во время загрузки кнопка «Повторить» недоступна (disabled).
- Состояние хранится в state.currentUrl, а не читается из DOM.

## Таблица результатов тестирования

1. Источник: products.json, условие: обычная загрузка

- Что увидел пользователь: синий блок «Загрузка товаров...» (модификатор status--loading), затем 8 карточек товаров с отформатированными ценами. Блок status скрыт.

2. Источник: missing.json, условие: файл не найден

- Что увидел пользователь: красный блок с текстом «Данные не найдены» (модификатор status--error), кнопка «Повторить» активна. Список карточек скрыт.

3. Источник: broken.json, условие: невалидный JSON

- Что увидел пользователь: красный блок с текстом «Сервер прислал испорченные данные» (модификатор status--error), кнопка «Повторить» активна. Список карточек скрыт.

4. Источник: products.json, условие: включен режим Offline (нет сети)

- Что увидел пользователь: красный блок с текстом «Нет соединения с сервером» (модификатор status--error), кнопка «Повторить» активна. Список карточек скрыт.

5. Источник: products.json, условие: выключен Offline, нажата кнопка «Повторить»

- Что увидел пользователь: синий блок «Загрузка товаров...», затем 8 карточек товаров. Блок status скрыт. Данные успешно восстановлены.

6. Источник: products.json, условие: быстрый клик по кнопке «Повторить» во время загрузки

- Что увидел пользователь: только один запрос выполняется (защита от повторных запросов через проверку state.status === 'loading'). Кнопка «Повторить» недоступна во время загрузки.

## Проверка дня (выполнена)

- В api.js вызов response.json() находится строго после проверки response.ok.
- Каждая ошибка поймана в try/catch и преобразуется в понятный текст через getErrorMessage.
- В консоли браузера нет «Uncaught (in promise)».
- Состояние запроса хранится в state.status и state.currentUrl, а не читается из DOM.
- Одна функция render() управляет всеми элементами интерфейса.
- Кнопка «Повторить» не меняет состояние напрямую — она вызывает loadProducts(), которая меняет state.status и вызывает render().
