# Day 3, Task 3.5: Чужие данные

## Что проверено

- Загрузка данных с внешнего API (https://jsonplaceholder.typicode.com/users).
- Загрузка данных из локального файла day3/data/users.json, содержащего намеренные ошибки:
  1. У двух пользователей полностью отсутствует поле company.
  2. У одного пользователя поле email равно null.
  3. У одного пользователя в поле name записана строка "<b>Имя</b>" (попытка XSS-атаки).

## Что получилось

1. Приложение не упало ни при одном из сценариев. Ошибок "Cannot read properties of undefined" или "Uncaught TypeError" в консоли нет.
2. Для пользователей без компании отобразился запасной текст: "Компания: Компания не указана". Это достигнуто благодаря опциональной цепочке user.company?.name и нулевому слиянию ??.
3. Для пользователя с email: null отобразился запасной текст: "Email не указан".
4. Для пользователя с именем "<b>Имя</b>" теги отобразились на странице как обычный текст, а не как жирный шрифт. Браузер не выполнил HTML-код. Это достигнуто благодаря использованию свойства textContent вместо innerHTML при вставке данных в карточку.
5. Переключение между внешним API и локальным файлом работает корректно, кнопка "Обновить" блокируется во время загрузки.

## Технические детали реализации

- Для безопасного доступа к вложенным свойствам использован оператор опциональной цепочки (?.). Например: user.address?.city. Если объекта address нет, выражение возвращает undefined, а не выбрасывает ошибку.
- Для подстановки значений по умолчанию использован оператор нулевого слияния (??). Например: user.email ?? 'Email не указан'. Он срабатывает только если левая часть равна null или undefined.
- Вся вставка данных в DOM выполняется через textContent. Это встроенная защита браузера от XSS: любые HTML-теги в строке автоматически экранируются и выводятся как текст.
